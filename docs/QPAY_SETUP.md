# QPay тохиргоо

Систем QPay Merchant API v2-г ашиглана: нэхэмжлэх үүсгэх → төлбөрийн callback хүлээж авах → төлбөрийг QPay-ээс дахин шалгаж баталгаажуулах.

## 1. QPay-ээс авах мэдээлэл

QPay-тэй merchant гэрээ байгуулсны дараа дараах мэдээллийг авна:

| Мэдээлэл | `.env` хувьсагч |
|---|---|
| Client ID (нэвтрэх нэр) | `QPAY_CLIENT_ID` |
| Client secret (нууц үг) | `QPAY_CLIENT_SECRET` |
| Invoice code (нэхэмжлэхийн код) | `QPAY_INVOICE_CODE` |

Эдгээрийг зөвхөн серверийн `.env` файлд хадгална. Код болон git-д бүү оруулаарай.

## 2. Горим

```ini
# Хөгжүүлэлт: QPay-д огт хандахгүй, төлбөрийн хуудсанд «Төлсөн гэж үзэх (тест)» товч гарна
QPAY_MODE=mock

# QPay-ийн тест орчин
QPAY_MODE=sandbox
QPAY_BASE_URL=https://merchant-sandbox.qpay.mn/v2
QPAY_CLIENT_ID=TEST_MERCHANT
QPAY_CLIENT_SECRET=123456
QPAY_INVOICE_CODE=TEST_INVOICE

# Жинхэнэ төлбөр
QPAY_MODE=live
QPAY_BASE_URL=https://merchant.qpay.mn/v2
QPAY_CLIENT_ID=...
QPAY_CLIENT_SECRET=...
QPAY_INVOICE_CODE=...
```

Дээрх sandbox тест мэдээллээр 2026-10-21-нд холболтыг шалгасан: токен авах, нэхэмжлэх үүсгэх, QR болон банкны апп-ын холбоос ирэх, төлбөр шалгах, нэхэмжлэх цуцлах бүгд ажилласан. Хэрэв QPay танд өөр тест мэдээлэл өгсөн бол түүнийг ашиглана.

`.env`-ийг өөрчилсний дараа серверийг дахин асаана (`sudo systemctl restart time-booking`).

## 3. Callback (заавал)

Нэхэмжлэх бүрт `callback_url` нь `BASE_URL/qpay/callback?b=<захиалгын нууц токен>` байна. Иймээс:

- `BASE_URL` нь интернэтээс хандах боломжтой **https** хаяг байх ёстой (жишээ: `https://www.example.mn`).
- `localhost` дээр QPay callback илгээж чадахгүй. Гэхдээ төлбөрийн хуудас 4 секунд тутам, сервер 30 секунд тутам QPay-ээс өөрөө шалгадаг тул тест орчинд ч төлбөр баталгаажна.

Аюулгүй байдал: callback-ийн агуулгад итгэхгүй. Callback ирэхэд систем QPay-ийн `/payment/check` API-аар төлбөрийг дахин шалгаж, төлөгдсөн дүн нэхэмжлэхийн дүнтэй тэнцүү эсвэл их үед л захиалгыг баталгаажуулна.

## 4. Төлбөрийн урсгал

1. Үйлчлүүлэгч цагаа сонгож «QPay-ээр төлөх» дарахад цаг `hold_minutes` (анхдагч 15) минут баригдаж, QPay нэхэмжлэх үүснэ.
2. Төлбөрийн хуудсанд утсан дээр банкны апп-ын товчнууд, компьютер дээр QR код харагдана.
3. Төлбөр орсны дараа (callback, хуудасны шалгалт эсвэл 30 секунд тутмын шалгалтаар) захиалга «Баталгаажсан» болж, SMS илгээгдэнэ.
4. Хугацаандаа төлөгдөөгүй бол цаг суллагдаж, QPay нэхэмжлэх цуцлагдана.
5. Цаг суллагдсаны дараа төлбөр орвол:
   - цаг сул хэвээр байвал захиалга баталгаажна;
   - өөр хүн цагийг авсан бол захиалга «Цуцалсан, буцаалт хийх» төлөвт орж, админ мөнгийг буцаана.

Бүх нэхэмжлэх, төлбөр `payments` хүснэгтэд хадгалагдаж, админы **Төлбөр** цэснээс харагдана.

## 5. Буцаалт

Систем мөнгийг автоматаар буцаадаггүй. Буцаалтыг QPay merchant системээр эсвэл банкны шилжүүлгээр хийгээд, админ самбарт «Буцаалт хийгдсэн» гэж тэмдэглэнэ (ADMIN_GUIDE.md, 6-р хэсэг).

## 6. Алдаа засах

| Шинж тэмдэг | Шалгах зүйл |
|---|---|
| «Төлбөрийн систем түр ажиллахгүй байна» | Серверийн лог (`journalctl -u time-booking`) дотор `[qpay]` мөрийг харна. Ихэвчлэн client ID, secret, invoice code буруу эсвэл `QPAY_BASE_URL` нь горимтойгоо таарахгүй байдаг. |
| Төлсөн ч баталгаажихгүй | `BASE_URL` https бөгөөд гаднаас хандах боломжтой эсэх. Nginx `/qpay/callback`-ийг блоклоогүй эсэх. Лог дотор `[qpay] callback` алдаа байгаа эсэх. |
| 401 алдаа | Client ID эсвэл secret буруу. |
